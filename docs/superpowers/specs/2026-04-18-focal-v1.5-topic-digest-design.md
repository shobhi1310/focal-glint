# Focal v1.5 — Enhanced Classification & Topic-Based Digest

**Goal:** Replace the overloaded 3-class notification system with a 4-class system (Urgent/Actionable/Digest/Noise), introduce topic-based clustering with cross-app semantic deduplication, and redesign the Digest screen as a "news shorts" topic feed with drill-down detail views.

**Builds on:** Focal v1 (Weeks 1-4) — notification capture, rules engine, LLM classification via LiteRT-LM + Gemma 3 1B, all working on Redmi Note 10 Pro.

**This becomes the new Week 5.** Original Week 5 (User Corrections) shifts to Week 6, original Week 6 (Polish) shifts to Week 7.

---

## 1. Problem Statement

The current 3-class system (Urgent/Informational/Noise) puts 112 out of 199 notifications into "Informational" — a catch-all bucket that's nearly as overwhelming as the raw notification shade. WhatsApp group chats, CRED bill reminders, Slack calendar events, and Swiggy delivery updates all live in one undifferentiated list.

Additionally, the same notification often arrives via multiple channels (CRED sends bill reminders via its own app, WhatsApp Business, SMS, and email), creating redundant entries that clutter the view.

Users need:
- A smarter classification that distinguishes "things I need to act on" from "things I want to catch up on"
- Topic-based grouping that clusters related notifications across apps
- A two-layer UX: quick-glance summaries → detailed drill-down

## 2. 4-Class Classification System

Replaces the current 3-class system.

| Category | What It Means | Examples | UX Treatment |
|----------|---------------|----------|--------------|
| **Urgent** | Needs immediate attention | OTP, "call me ASAP", meeting in 1 min | Always visible, top of every view |
| **Actionable** | Requires action, not right now | CRED bill due May 6, rate Swiggy order, reply to boss | Smart card with what + when + action |
| **Digest** | Context to catch up on when free | WhatsApp group chat, Telegram channels, newsletters | LLM-generated summary, tap for thread |
| **Noise** | Promotional, duplicate, irrelevant | Rapido 50% off, 3rd reminder of same bill via different channel | Hidden, counted, collapsed |

### Classification Rules Migration

- `ClassificationResult.INFORMATIONAL` → removed
- `ClassificationResult.ACTIONABLE` → new constant
- `ClassificationResult.DIGEST` → new constant
- Messaging apps (WhatsApp, Telegram, Slack, Discord, Google Messages) → default rule changes from `informational` to `digest`
- Transactional apps (Swiggy, Zomato) → default rule changes from `informational` to `actionable`
- LLM classification prompt updated to output 4 categories instead of 3

### LLM Classification Prompt (updated)

```
You are a notification classifier. Categorize as: urgent, actionable, digest, or noise.

- urgent: needs immediate attention (OTP, emergency, meeting right now)
- actionable: requires user action but not immediately (bill due, order to rate, reply needed)
- digest: context to catch up on later (chat messages, news, updates)
- noise: promotional, duplicate, or irrelevant

App: {app_name} | Sender: {title} | Time: {time}
Message: "{message}"

{app_profile}
{recent_corrections}

Respond in JSON only:
{"category": "...", "reason": "...", "confidence": 0.0-1.0}
```

## 3. Three-Page UI Architecture

### Page 1: Digest (Home) — Topic Shorts

The main screen. Shows topic cards like a news shorts feed. Each card is a one-glance summary of a cluster of related notifications.

**Layout:**
- Urgent banner at top (if any urgent notifications exist)
- Scrollable list of topic cards
- Each card shows: category badge, headline, one-line LLM summary, source app pills, channel count
- Noise count footer: "47 noise notifications hidden"
- Pull-to-refresh triggers background classification + topic regeneration

**Topic card structure:**
```
┌─────────────────────────────────────┐
│ 🟡 ACTION NEEDED       via 3 channels│
│                                      │
│ Credit Card Bill Due                 │
│ HDFC card ending 6512 · Rs 15,221   │
│ · Due May 6                          │
│                                      │
│ [CRED] [WhatsApp] [Gmail]           │
│                           Tap for →  │
└─────────────────────────────────────┘
```

### Page 1 → Child: Topic Detail

Tapping a topic card navigates to the detail view. Content depends on topic type.

**Template-based detail (known app types):**
- **Billing** (CRED, banks): Structured card with amount, due date, card number, status + action button ("Open CRED to Pay")
- **Delivery** (Swiggy, Zomato, Amazon): Status timeline (ordered → preparing → out for delivery → delivered)
- **Calendar** (Slack, Google Calendar): Event card with name, time, location
- **Messaging** (WhatsApp, Telegram): LLM summary + conversation thread

**LLM-generated detail (everything else):**
- Richer summary paragraph generated by LLM
- All source notifications listed with channel and timestamp

**All detail views show:**
- Category badge and headline
- Smart card or LLM summary
- "Received via N channels" section with individual source notifications
- Action button (if applicable — opens the relevant app)

### Page 2: All Notifications (Categorized)

Traditional categorized view showing every individual notification. Four collapsible sections: Urgent / Actionable / Digest / Noise. Each notification expandable. Long-press to recategorize (Week 6 feature).

### Navigation

- **Bottom nav:** Digest (💎) | All (📋) | Settings (⚙️)
- **Digest → Topic Detail:** Forward navigation on tap, back button returns
- **Default tab:** Digest is home

## 4. Topic Clustering Engine

### Pipeline (runs in ClassificationWorker)

```
Step 1: Classify pending notifications (existing)
  Layer 1 (Rules) → Layer 2 (LLM), now with 4 categories

Step 2: Group by app (fast, no LLM)
  All recent notifications grouped by packageName

Step 3: Topic Clustering (NEW)
  3a: Create initial topic per app group
      headline = app name, summary = existing summarizer output
  3b: LLM Merge Pass — semantic deduplication
      Feed all topic headlines + summaries to LLM
      Ask: "Which groups are about the same thing?"
      Response: JSON array of merged group indices
  3c: Merge matched groups into single topics
      Combined notification_ids, merged source_apps

Step 4: Generate Detail Views (NEW)
  For each topic:
    Template match? (billing, delivery, calendar)
      YES → Extract structured data into detail_json
      NO  → LLM generates detail_summary

Step 5: Save topics to DB
  Insert/update TopicEntity rows
  Link notifications via topic_id
```

### LLM Merge Prompt

```
Here are notification groups from the last 24 hours:
1. CRED App: HDFC card bill Rs 15,221 due May 6
2. WhatsApp (CRED): HDFC card payment reminder due May 6
3. Gmail: HDFC Credit Card Statement — Amount due Rs 15,221
4. WhatsApp (Family Group): Planning weekend trip to Manali, 23 messages
5. Slack: Hackathon pair coding session at 2 PM, sprint retro notes

Which groups are about the same topic? Respond as JSON array of arrays:
[[indices of same topic], [indices of same topic], ...]
```

Expected response: `[[1,2,3],[4],[5]]`

### Performance Budget (Snapdragon 720G)

| Operation | Latency | When |
|-----------|---------|------|
| Classification (existing) | ~3-5s per notification | Batch, background |
| Topic merge pass | ~5-10s (one LLM call) | After classification |
| Detail generation (per non-template topic) | ~5-8s | After merge |
| **Total added per batch** | **~20-40s** | All background |

Topics cached in DB — only regenerated when new notifications arrive.

## 5. Data Model Changes

### New Table: topics

| Column | Type | Description |
|--------|------|-------------|
| id | TEXT (PK, UUID) | Unique identifier |
| headline | TEXT | Topic title ("Credit Card Bill Due") |
| summary | TEXT | LLM-generated one-liner |
| category | TEXT | urgent / actionable / digest / noise |
| notification_ids | TEXT | JSON array of notification IDs in this topic |
| source_apps | TEXT | JSON array of app names (["CRED", "WhatsApp", "Gmail"]) |
| channel_count | INT | Number of distinct source apps |
| detail_json | TEXT? | Structured detail for template smart cards |
| detail_summary | TEXT? | LLM-generated detail text |
| action_label | TEXT? | Action button label ("Open CRED to Pay") |
| action_package | TEXT? | Package name to open on action tap |
| created_at | LONG | Creation timestamp |
| updated_at | LONG | Last update timestamp |
| is_read | BOOL | Whether user has tapped into detail (default false) |

**Indexes:** `(category, updated_at)`, `(updated_at)`

### Changes to Existing Tables

**notifications:**
- Add column: `topic_id TEXT?` — FK to topics table (nullable, default null)
- Migrate: all `category = "informational"` → `"digest"`

**rules:**
- Migrate: messaging app rules `category = "informational"` → `"digest"`
- Migrate: transactional app rules `category = "informational"` → `"actionable"`

**ClassificationResult constants:**
- Add: `ACTIONABLE = "actionable"`, `DIGEST = "digest"`
- Remove: `INFORMATIONAL = "informational"`

### Database Migration (Room v1 → v2)

```sql
-- Create topics table
CREATE TABLE IF NOT EXISTS topics (
    id TEXT PRIMARY KEY NOT NULL,
    headline TEXT NOT NULL,
    summary TEXT NOT NULL,
    category TEXT NOT NULL,
    notification_ids TEXT NOT NULL,
    source_apps TEXT NOT NULL,
    channel_count INTEGER NOT NULL DEFAULT 1,
    detail_json TEXT,
    detail_summary TEXT,
    action_label TEXT,
    action_package TEXT,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    is_read INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS index_topics_category_updated ON topics(category, updated_at);
CREATE INDEX IF NOT EXISTS index_topics_updated ON topics(updated_at);

-- Add topic_id to notifications
ALTER TABLE notifications ADD COLUMN topic_id TEXT;

-- Migrate informational → digest
UPDATE notifications SET category = 'digest' WHERE category = 'informational';

-- Migrate rules
UPDATE rules SET category = 'digest' WHERE category = 'informational' AND app IN (
    'com.whatsapp', 'org.telegram.messenger', 'com.Slack', 'com.discord',
    'com.google.android.apps.messaging'
);
UPDATE rules SET category = 'actionable' WHERE category = 'informational' AND app IN (
    'in.swiggy.android', 'com.application.zomato'
);
UPDATE rules SET category = 'digest' WHERE category = 'informational';
```

## 8. Detail Templates

### Billing (CRED, banks)

Regex/keyword extraction from notification content:
- Amount: `Rs\s*[\d,]+\.?\d*` or `₹[\d,]+`
- Due date: `due\s*(on\s*)?(\w+\s+\d{1,2})`
- Card: `(card|ending)\s*(\d{4})`

Output `detail_json`:
```json
{"type": "billing", "amount": "15221", "currency": "INR", "due_date": "2026-05-06", "card_last4": "6512", "status": "unpaid"}
```

### Delivery (Swiggy, Zomato, Amazon)

Keyword extraction:
- Status: "ordered" / "preparing" / "out for delivery" / "delivered"
- Item: text after "your order" or order ID

Output `detail_json`:
```json
{"type": "delivery", "status": "delivered", "time": "8:32 PM", "item": "Order #12345"}
```

### Calendar (Slack, Google Calendar)

Keyword extraction:
- Event: text after "until this event:" or "Reminder:"
- Time: time pattern extraction

Output `detail_json`:
```json
{"type": "calendar", "event": "hackathon pair coding", "time": "2:00 PM", "location": null}
```

### Everything else → LLM detail_summary

The LLM generates a 2-3 sentence summary with context, key facts, and any action items.
