# Focal v2 — Narrative Digest Redesign

**Goal:** Replace the broken 4-class categorized notification list with a 2-class system (matters/noise) and a narrative-driven Digest page that reads like a personal briefing — not a notification list.

**Core insight:** The Digest page should answer "what happened while I was busy?" in 30 seconds. Each item is a story the LLM writes in plain language. No category badges, no color coding. The language and position convey importance.

**Builds on:** Focal v1.5 (4-class system, TopicEngine, LiteRT-LM). This is a redesign of the classification and presentation layers.

---

## 1. Problem Statement

The current Digest page is functionally identical to the All page — both show raw notification content with category labels. The LLM produces empty summaries ("Here's a summary:."). Classification is inaccurate (NDTV news = urgent, Paytm cashback = actionable). Users see no value in opening the Digest over just reading their notification shade.

## 2. Classification: 2-Class System

Replace the 4-class system (urgent/actionable/digest/noise) with:

**Matters** — Notifications that, when stitched together, tell a story the user would want to read
- Financial: OTP + transaction alert + bank debit = spending story
- Personal: WhatsApp messages from friends = conversation story
- Logistics: Swiggy order + delivery = delivery story
- Schedule: Calendar reminders, meeting alerts

**Noise** — Notifications with zero narrative value
- Promotions, cashback offers, discount codes
- News articles (unless user actively follows — learnable via corrections)
- App marketing, rate-us prompts
- Duplicate cross-channel notifications (after dedup)

### Classification Rules

**Layer 1 (Rules — instant):**
- Known promo apps → noise: Rapido, Flipkart, Amazon, Myntra, Snapdeal, Dream11, Paytm, PhonePe, Google Pay
- Known messaging apps → matters: WhatsApp, Telegram, Slack, Discord, Google Messages
- Known financial apps → matters: CRED, bank SMS senders
- Known logistics apps → matters: Swiggy, Zomato

**Layer 2 (LLM — for unmatched):**
```
Does this notification matter personally to the user, or is it generic/promotional?

Notification from {app_name}:
"{title}: {content}"

Answer with JSON: {"matters": true/false, "reason": "..."}
```

Simple binary. No urgency levels.

### DB Constants

```kotlin
companion object {
    const val MATTERS = "matters"
    const val NOISE = "noise"
    const val UNCATEGORIZED = "uncategorized"
}
```

### Migration

All existing `urgent`, `actionable`, `digest` → `matters`. Existing `noise` stays `noise`.

## 3. Story Generation Pipeline

Runs in ClassificationWorker after classification (triggered 30s after each notification).

### Step 1: Classify
Existing pipeline — rules first, LLM for unmatched. Now binary (matters/noise).

### Step 2: Cluster into Story Groups
Group "matters" notifications by semantic similarity:

1. Group by app (fast, no LLM)
2. Within app groups, sub-group by conversation/sender
3. LLM merge pass: combine cross-app groups about the same thing
   - ICICI SMS + Truecaller alert + Gmail bank alert → one financial story
   - Same CRED bill via app + WhatsApp + email → one story

### Step 3: Generate Narrative Per Story
For each story group, LLM generates ONE natural sentence:

```
You are a personal assistant briefing the user about their notifications.
Write ONE natural sentence summarizing what happened.
Be specific — include names, amounts, times, places.
Do NOT say "Here's a summary" or "Summary:" — just state what happened.
Write as if you're telling a friend.

Notifications:
[1] Truecaller: Rs 44,000.00 spent on ICICI Bank Card XX2002
[2] Gmail: ICICI Bank transaction alert — Rs 44,000 at Amazon

Write one sentence:
```

Expected output: "Rs 44,000 was charged on your ICICI card at Amazon."

NOT: "Here's a summary: transaction alert."

### Step 4: Generate Daily Briefing
Feed ALL story narratives to LLM:

```
You are writing a 2-3 line personal briefing for the user.
Summarize their day based on these stories. Be concise and specific.
Mention the most important things first. End with how many items were hidden as noise.

Stories:
- Rs 44,000 was charged on your ICICI card at Amazon
- Darahas wants to know when you're coming to Bangalore
- Family group is planning a weekend trip, 23 messages
- IRCTC booking confirmed, PNR 4943911221

Hidden: 15 noise notifications

Write the briefing:
```

Expected: "You had a Rs 44K charge on your ICICI card at Amazon — check if that was you. Darahas wants to know your Bangalore travel plans. Your family is planning a weekend trip (23 messages to catch up on). 15 promos hidden."

### Step 5: Store
- Each story → TopicEntity (headline = narrative sentence, source notification IDs)
- Daily briefing → stored in SharedPreferences or a separate table row
- Topics table: remove `category` dependency on 4-class, just use for ordering

## 4. Digest Page UI

### Top: Daily Briefing
2-3 lines of text generated by LLM. Reads like a personal assistant note.

### Middle: Story Cards
Ordered by relevance (financial → personal → logistics → general).
Each card:
- **Headline**: One LLM-generated sentence in plain language
- **Source pills**: App names that contributed (WhatsApp, Gmail, etc.)
- **Tap**: Opens detail view

NO category badges. NO color coding. NO "URGENT" / "DIGEST" / "ACTIONABLE" labels.
The language does the work — "Rs 44K charged on your card" naturally feels important.

### Bottom: Noise Footer
"15 promotional notifications hidden" — tappable to see All page.

### Detail View (on tap)
- The story headline at top
- LLM-generated insight (if available): "This charge is higher than your usual Amazon spending"
- Source notifications listed with app name, time, content
- Structured data card if applicable (billing: amount/card/date, delivery: status)
- Action button if applicable ("Open CRED", "Call Bank")

## 5. All Page
Shows everything:
- **Matters** section (expanded) — individual notifications, not stories
- **Noise** section (collapsed) — count + expandable

Uses the existing CategorySection composable with 2 sections instead of 4.

## 7. Prompt Quality Rules

The #1 lesson from v1.5: **the LLM prompt determines everything.** Bad prompts = "Here's a summary:." Good prompts = "Rs 44K charged on your ICICI card at Amazon."

Rules for all prompts:
1. Never ask the LLM to say "summary" or "here's" — it copies those words
2. Always give concrete examples of expected output
3. Always say "Write as if telling a friend"
4. Always include specific data (names, amounts, times) in the prompt so the LLM echoes them
5. Keep prompts under 500 tokens — Gemma 3 1B loses coherence on long prompts
6. For binary classification, force JSON output: `{"matters": true/false}`
7. For narratives, force single sentence: "Write ONE sentence. No preamble."
